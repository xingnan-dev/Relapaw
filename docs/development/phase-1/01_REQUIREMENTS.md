# Phase 1 Requirements Analysis

## 问题

Phase 0/0.1 已建立宠物档案、Episode/Observation/OwnerInterpretation 骨架和四页低保真入口，但用户仍无法完成真正的记录闭环：记录创建缺少结构化字段与事务边界，Timeline 不能完整管理记录，复评无法关联原记录，Observation Plan 也没有每日执行项。

## 用户价值

- 主人可以快速记下当时发生的事实，并把自己的猜测单独保存。
- 每条记录保留发生时间、记录时间、来源、上下文和对象引用，可供未来 Evidence 与 Baseline 使用。
- 用户可以在 Timeline 中查看、筛选、编辑和删除自己的记录。
- 用户可以为一次 Episode 安排复评，并记录持续、改善、加重或新情况。
- 对健康风险的处理是显式人工流程；系统不诊断，也不伪装成 AI 判断。

## 核心原则

1. `raw_owner_input` 是原始输入，不自动等同于客观事实。
2. Observation 与 OwnerInterpretation 必须是不同实体、字段、API 和视觉区块。
3. Observation 只描述可见、可听、可计量或明确发生的事实。
4. 每次修改保留 `created_at` 与 `updated_at`；删除在 Phase 1 采用明确确认后的物理删除，不虚构审计历史。
5. Safety Check 由用户显式选择和确认；规则自动判定、医疗推断留到后续安全阶段评审。
6. Follow-up 是新记录，必须引用原 Episode，不能覆盖原始内容。

## 主要用户故事

### 创建记录

作为宠物主人，我可以选择当前宠物与发生时间，输入原始描述，再分别填写“发生了什么”和“我的理解”，从而保存一条不混淆事实与解释的 Episode。

### 补充上下文

我可以记录地点、在场对象、刚发生的事件、持续时间、频率、强度以及饮食、饮水、排泄、睡眠和活动变化。未填写的字段保持未知，不以默认正常值代替。

### 安全筛查

保存前，我需要确认是否存在呼吸困难、持续抽搐、昏厥/无法站立、严重出血、疑似中毒或其他紧急情况。若选择存在风险，界面持续显示尽快联系兽医的提示，并允许建立人工 VeterinaryEscalation。

### Timeline 管理

我可以按宠物、时间范围和记录类型筛选，查看详情，并编辑或删除自己创建的记录。删除必须二次确认。

### 复评

我可以选择 2 小时、次日、3 天或自定义时间进行复评；复评记录持续、改善、加重、已消失或出现新情况，并与原 Episode 双向可见。

### 观察计划

我可以创建一个带目标、起止时间和每日观察项的计划，将新 Episode 关联到计划，并完成或取消计划。

## 非功能要求

- 外部 datetime 必须带时区并在服务端归一到 UTC。
- 新数据库变更必须通过独立 Alembic revision，不修改初始 revision。
- 组合创建记录要么全部成功，要么全部回滚。
- 所有资源读写均校验宠物或父记录存在，返回统一错误契约。
- 前后端覆盖 loading、empty、content、validation error、network error 与 retry。
- 键盘、屏幕阅读器和 reduced motion 延续 Phase 0.1 约束。

## 不在范围

- LLM、RAG、Agent、自动拆分文本、自动情绪/意图判断。
- 自动医疗诊断、自动风险评分或基于关键词的伪智能诊断。
- 图片、音频、视频上传和识别。
- 量化 Baseline、趋势算法、伪精确百分比。
- 通知系统、后台调度、账号、多设备同步。
- Pet↔Pet 关系与多人协作。
