# Architecture Decisions

## UX-001：视觉层覆盖业务层，不重写状态机

保留现有 React 状态、API 调用和数据结构。优先抽取展示组件、页面布局和状态容器，避免在品牌精修中混入业务重构。

## UX-002：扩展现有 token 与 primitive

继续使用 CSS custom properties 和原生 HTML，扩展排版、容器、层级、图标尺寸、状态 badge、section header、empty state 与 action group；不并行建立第二套设计系统。

## UX-003：移动优先，桌面自适应分栏

手机保持单列和底部导航；较宽视口使用受控最大宽度与可选主辅分栏，让详情、来源和操作形成清晰关系。布局变化不得改变 DOM 中的信息顺序和键盘顺序。

## UX-004：品牌资产必须仓库原生、来源可审计

Logo、图标和装饰优先使用自有 SVG/CSS 资产。任何第三方字体、图标或素材必须记录许可与来源；未完成许可检查前不引入远程字体或图库素材。

## UX-005：安全与资格状态具有最高展示约束

Safety 阻断、兽医升级、Evidence 来源、Uncertainty、模型来源、用户决定和 `NOT_QUALIFIED` 不得仅靠颜色表达，也不得被折叠到默认不可见区域。视觉组件不改变其业务含义。

## UX-006：截图回归与功能回归并行

每个实施切片都必须通过既有 Vitest/build；核心视口与状态使用固定数据进行截图验收。截图用于发现布局回归，不替代语义、键盘和业务测试。
