状态：独立章节已形成；最终截图、录屏、commit hash 与提交版式待 Release Candidate 阶段补齐。

## 一、使用的 AI Coding 工具

本项目使用 **OpenAI Codex（桌面工作区代理）** 参与完整软件开发生命周期，而不是只在局部生成代码。Codex 的具体用途包括：

- 理解并拆解用户需求，识别范围、非目标与验收条件；
- 审计既有前后端、数据库迁移、测试、未提交修改和 Git 历史；
- 设计 API、数据契约、Safety、Evidence、事务与错误语义；
- 实现 React/TypeScript 前端、FastAPI/Python 后端、测试和开发文档；
- 运行自动测试、production build、迁移与静态检查并定位失败；
- 对 AI 生成代码执行独立 Review，修复后重新完整回归；
- 根据真实浏览器截图和人工反馈迭代 UI/UX、响应式与交互；
- 维护工具用途、交互案例、第三方来源、风险和 Git 证据映射。

Codex 是开发工具；Relapaw 产品运行时可接入的 Qwen/OpenAI-compatible Provider 是业务模型。两者的职责、数据和证据相互独立，不能混称。

## 二、AI 嵌入的完整生命周期

```text
人工提出目标与边界
→ Codex 审计仓库、能力和风险
→ 人与 AI 明确需求、架构、范围与验收条件
→ Codex 按垂直切片实现代码和测试
→ 自动检查暴露问题
→ Codex 独立 Review 自身生成物
→ Codex 修复并重新完整回归
→ 人工在真实界面验收并否决或调整方向
→ Codex 更新过程、风险、来源和证据文档
→ 人工单独授权 commit
→ 核对本地提交
→ 人工单独授权 push
→ 核对远端证据
```

这套流程覆盖发现、设计、开发、验证、Review、体验、交付和后续运营准备。测试通过不能替代人工体验验收；人工喜欢某个方向也不能替代 Safety、契约和回归测试。

## 三、完整人机交互案例：从“卡片很多”到真实任务闭环

### 1. 人工发现问题

用户在真实页面中指出：多个卡片跳往同一个“足迹”页面、部分卡片看似可点击却没有行为、记录流程顶部步骤看似按钮但不能操作、保存记录后没有直接看到刚创建的内容。用户要求先分析项目是否真正需要这些入口，再决定是否修改。

### 2. AI 审计与解释

Codex 对照页面文案、React 回调、API 和真实数据能力，将入口划分为核心操作、条件出现、纯展示和重复入口，并得到关键结论：

- 第二个主导航实际承担“新建记录”，真正的 AI 理解位于记录详情；
- “回来看看”只有存在到期复评时才有任务；
- “日常的变化”应消费 Baseline，而不是泛化跳转 Timeline；
- “关系足迹”“生活事件”等卡片没有独立能力，制造了虚假复杂度；
- 记录步骤条和保存后的去向没有形成连续操作闭环。

### 3. 人工决定

用户确认先做结构减法，不继续增加卡片；随后明确要求步骤条可操作，并继续推进保存后的真实闭环。人工同时保留了 Safety、Evidence、长期记忆和 Baseline 等确有数据能力的功能。

### 4. AI 实现

- 将“理解”入口改为清晰的“记录”任务；
- 无行为日期改为纯展示，删除空状态中的错误跳转；
- 删除或降级没有独立能力的重复功能卡；
- 记录步骤条支持跳到对应表单分区；
- 保存成功后直接打开新 Episode 详情，而不是回到泛化列表；
- 长期记忆候选创建后可直达“我们”页对应分区；
- 观察计划加载失败不再伪装成“没有计划”，改为明确错误与重试，并保留已填写草稿。

### 5. 验证与证据

- 前端：`npm test -- --run`，69 项通过；
- 前端：`npm run build`，production build 通过；
- 后端：114 项测试通过；
- 代码格式：`git diff --check` 通过；
- 人工证据：用户提供的移动端/桌面截图、逐轮反馈和最终操作确认；
- 代码证据：当前工作区 diff；正式 commit hash 将在人工授权提交后补入 `06_COMMIT_AND_EVIDENCE_MAP.md`。

### 6. 该案例体现的 AI 原生方法

AI 没有把“生成更多界面”当作成功，而是把用户反馈、代码事实、数据能力、错误状态和测试共同作为裁决依据。实现完成后又通过异常路径审计发现静默失败，并补上可恢复交互。这体现了“人类目标、AI 执行、证据裁决”和“失败可见、可审计、可重试”。

## 四、人工始终保留的决定权

- 产品范围、视觉方向、是否接受某版体验由用户决定；
- Safety 与是否联系兽医由人工确认，模型不能诊断；
- Claim 必须逐条确认或拒绝，不能自动成为事实或 Baseline；
- 真实付费 Provider 请求、commit 和 push 分别需要明确授权；
- 用户否决的视觉版本和模型资格失败不会从过程证据中删除。
