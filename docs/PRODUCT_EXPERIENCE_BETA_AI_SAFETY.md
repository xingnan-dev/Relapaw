# Relapaw Beta AI 与受控知识安全边界

## 产品角色

AI 只整理用户已经保存的记录、提出待确认候选、比较同一宠物的近期记录，并帮助组织给兽医看的时间线。它不是诊断工具，不替代检查，不提供治疗、药物或剂量。

## 调用前门禁

1. AI 默认为关闭；密钥存在不能开启功能。
2. provider、模型、地域端点策略、两个提示/输入/输出契约、受控知识集合版本及资格证据 SHA-256 必须同时匹配仓库清单和数据库中的 `APPROVED` 资格记录。记录缺失、被撤销、证据文件变化或任一字段漂移均拒绝调用。Qwen 资格记录只保存 HTTPS、北京地域域名后缀和兼容 API 路径，不保存私有工作空间主机前缀。
3. 当前记录必须有人工作出的 `NORMAL` 安全确认；否则在调用供应商前停止。
4. 模型等待期间若安全状态变化，丢弃模型输出并保存为 `BLOCKED_BY_SAFETY`。
5. 照护者背景只有在用户明确同意的字段白名单内才可进入上下文；本版七段式上下文默认不读取照护者背景。

所选真实供应商为阿里云百炼 Qwen 北京地域，候选固定版本为 `qwen3.7-plus-2026-05-26`。2026-10-26 的第三轮历史结果是：`text-understanding/v7-verbatim-fact-extraction` 两例通过自动及人工复核；`assistant-guidance/v3-item-citations-safety-boundary` 英文截断历史用例通过，但中文用例因缺少模型知识逐项引用被确定性门禁拒绝，因此当时组合为 `NOT_QUALIFIED`。随后 guidance v4 的第四轮通过并与 v7 组合登记为可撤销资格记录；同日 facts v7 与 guidance v4 各一次真实产品 smoke 均成功。AI 开关仍保持关闭。

`text-understanding/v7-verbatim-fact-extraction` 只能返回 `raw_owner_input` 中逐字、连续的原文片段和 RAW_OWNER_INPUT 证据键，并分别归入可观察事实候选或主人明确表达的理解。应用层再次验证逐字来源、显式理解标记、非观察性词语、重复分类、证据类型，以及片段与用户已保存的对应事实/理解镜片是否归一化重合；没有对应人工镜片时必须为空。新抽取不能进入长期记忆。第三轮真实评估证明两例 v7 抽取通过，但组合仍因 guidance 用例失败而不合格。

guidance 的离线修复已升级为 `assistant-guidance/v4-versioned-claim-citations`。每条知识型主张必须以段落和零基条目下标绑定引用，并逐字复制输入中的 citation ID、知识 ID 和知识版本；服务端依据本次批准知识快照精确核验三者。无批准知识时，“可能相关背景”“继续观察”和引用数组必须为空，并在“不能确定”中说明没有可用的批准背景资料。2026-10-26 guidance-only 第四轮 2/2 通过自动及人工复核；结合复用的 v7 2/2 证据，组合评估为 QUALIFIED。0027 已登记可撤销的运行时记录，但 AI 开关仍为 false，启用需要单独授权。

## 知识与输出门禁

- 运行时不提供互联网搜索或工具，只传入仓库中 `APPROVED` 且未撤回的受控条目。
- 受控集合当前只包含非医疗的记录方法；医疗分流仍等待执业兽医审批。
- 背景与观察建议必须引用本次冻结的受控知识 ID；越界或缺失引用会拒绝整个输出。
- “记录显示”和“主人理解”每一项必须引用本次输入中的记录 ID；越界或缺失血缘会拒绝整个输出。
- 输出包含确定诊断、剂量、给药、处方或替代兽医检查指令时会被应用侧拒绝。
- 未知内容必须进入“目前不能确定什么”，不能补造事实。

## 七段式用户结构

1. 我从记录中看到什么；
2. 哪些是你的理解；
3. 可能相关的背景；
4. 目前不能确定什么；
5. 建议继续观察什么；
6. 何时应联系兽医；
7. 使用了哪些资料。

模型结果不会覆盖原话、Observation、主人理解、Safety、Baseline 或长期记忆。候选理解必须由用户逐条确认；进入长期记忆仍需第二次显式纳入。

## 数据生命周期

每次运行保存 request ID、状态、用途、provider、模型和解析到的模型版本、提示/输入/输出契约版本、输入快照、知识快照、标准化输出、来源记录更新时间、错误码和完成时间。运行受租户链保护，进入账户导出，并在来源记录或账户删除时删除。
