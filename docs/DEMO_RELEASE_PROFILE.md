# Relapaw 比赛与演示版本发布形态

状态：**已冻结**  
版本：1.0  
冻结日期：2026-10-16  
适用范围：账号体系实施前的比赛展示、评审和本地产品演示  

## 1. 发布决定

当前发布形态冻结为：

> **本地可重复演示为主；受控线上预览为可选；只使用合成数据；不接入真实外部用户。**

这不是面向真实用户的公开产品发布，也不能替代 [真实产品首发契约](LAUNCH_PRODUCT_SCOPE.md) 中的外部多人 Beta 门禁。

当前不需要：

- 购买产品域名；
- 配置正式发信邮箱；
- 实现账号、OTP 或登录；
- 部署 PostgreSQL；
- 为演示连接真实用户数据；
- 把当前 `NOT_QUALIFIED` 模型组合包装成已可用产品能力。

## 2. 三种环境的边界

| 环境 | 当前是否采用 | 数据 | 访问边界 | 用途 |
|---|---|---|---|---|
| 本地演示 | 是，唯一正式演示基线 | 固定合成数据 | 仅 `127.0.0.1` | 比赛展示、录屏、人工验收 |
| 受控线上预览 | 可选，非当前必需 | 可随时重置的合成数据 | 平台访问控制或一次性私密链接 | 远程评审无法运行本地环境时使用 |
| 外部多人 Beta | 否 | 真实用户数据 | 应用账号、租户隔离、隐私和数据权利 | 未来真实产品首发 |

任何线上地址只要允许不受控公众提交或长期保存数据，就不再属于“受控预览”，必须先完成外部多人 Beta 的账号和隐私门禁。

## 3. 本地演示目标架构

### 3.1 运行形态

目标是从仓库根目录通过一个受控入口启动：

```text
演示预检
→ 前端 production build
→ 对独立演示数据库执行 Alembic migration
→ 在空库或明确重置后写入版本化合成数据
→ 启动 FastAPI
→ 由同一 localhost Origin 提供 API 与构建后的前端
→ 打开演示首页
```

冻结要求：

- 使用构建后的前端，不以 Vite HMR 开发服务器作为正式演示入口；
- FastAPI 只监听 `127.0.0.1`，不得监听局域网或公网地址；
- 演示数据库使用独立明确路径，例如 `backend/.demo/relapaw-demo.db`；
- 演示流程不得读取或覆盖默认开发数据库 `backend/relapaw.db`；
- 演示模式使用显式配置 `RELAPAW_ENV=demo`，缺少时拒绝运行 reset/seed；
- 前端与 API 同源，演示模式不需要开放跨域来源；
- SQLite 仅用于本地演示，不作为真实多人生产数据库。

### 3.2 建议的交付入口

代码实施阶段提供以下命令或等价入口：

```text
scripts/demo.ps1 start
scripts/demo.ps1 reset
scripts/demo.ps1 verify
scripts/demo.ps1 stop
```

职责：

- `start`：检查依赖、构建、迁移、必要时初始化合成数据并启动；
- `reset`：只重建经过绝对路径校验的演示数据库；
- `verify`：检查数据库版本、数据集版本、后端健康、前端资源和关键 API；
- `stop`：只停止本脚本启动并记录 PID 的演示进程。

`reset` 属于破坏性操作，必须同时满足：

1. `RELAPAW_ENV=demo`；
2. 目标绝对路径位于仓库内固定 `.demo` 目录；
3. 数据库文件名与允许列表完全匹配；
4. 不允许通过通用环境变量、通配符或用户输入拼接删除路径；
5. 命令输出实际重置的绝对路径。

### 3.3 依赖策略

- 演示机器预先安装项目已声明版本范围内的 Python 与 Node.js；
- 正式演示前执行 `npm ci` 和后端依赖安装，不在现场下载依赖；
- 不以 Docker 为当前硬依赖，避免比赛机器没有 Docker Desktop；
- Docker 化可作为后续可选交付，但不能替代原生 Windows 演示路径；
- 演示启动不自动修改全局 Python、Node、PowerShell 或系统防火墙配置。

## 4. 合成演示数据

### 4.1 数据原则

演示数据必须：

- 完全合成，不来自真实主人、宠物、聊天、照片或医疗记录；
- 使用明显虚构但自然的宠物身份和情境；
- 不包含真实邮箱、电话、地址、医院、兽医或可识别人物；
- 固定版本并可重复生成相同业务状态；
- 与自动测试 fixture 分开，面向产品叙事而不是只覆盖代码分支；
- 在 UI 和演示文档中标明“合成演示数据”。

### 4.2 数据集版本

首个数据集标识冻结为：

```text
relapaw-demo/v1-observe-review-baseline
```

必须覆盖：

1. 一只主要演示宠物，具备基本档案；
2. 至少 7 天的结构化 Episode，Observation 与 Interpretation 均有清晰例子；
3. 一条需要今日完成的复评和一条已完成复评；
4. 一项进行中的观察计划及关联记录；
5. `NORMAL` Safety 主路径；
6. 一条独立的 `ESCALATE_TO_VET` 安全案例，用于展示模型不会被调用；
7. 7/30/90/all 中至少包含 `READY`、`INSUFFICIENT_DATA` 和 `EMPTY` 的可解释状态；
8. Baseline 的样本量、算法版本、趋势边界和来源下钻；
9. 编辑或来源变化后的 stale 示例；
10. loading、empty、error 等状态通过专用预览或测试展示，不向主数据集写入伪错误。

### 4.3 可重复性

- Seed 使用稳定业务标识或确定性查找，不依赖数据库自增 ID 的具体数值；
- 同一空库运行一次后得到确定状态；重复运行不得无限复制数据；
- Seed 写入要么全部成功，要么全部回滚；
- 数据集记录 `dataset_version` 和 `seeded_at`；
- 应用版本与数据集版本不兼容时，`verify` 必须失败并要求 reset；
- 所有相对日期以演示启动时的基准时间生成，保证“今日到期”等页面状态始终可展示。

## 5. AI 与网络依赖

### 5.1 默认行为

本地演示默认：

- 不配置 `OPENAI_API_KEY`；
- `RELAPAW_AI_ENABLED=false`；
- 不发送任何真实 Provider 请求；
- 不允许通过直接调用 API 绕过关闭状态；
- UI 不展示“开始 AI 分析”主动作；
- 明确保留 `qwen/qwen3.8-flash + text-understanding/v5-grounded-claims = NOT_QUALIFIED` 结论。

### 5.2 如何展示 AI Coding 与 Evaluation

比赛中的 AI 内容分成两类，不能混淆：

- **AI Coding 过程**：展示开发工具、需求—实现—Review—修复—测试证据；不依赖运行时模型在线；
- **产品运行时 AI Evaluation**：通过已冻结的离线/录制评估报告展示 Evidence、Uncertainty、安全阻断和 `NOT_QUALIFIED` 结论。

如果演示需要展示历史 Claim UI，只能使用明确标注为“录制评估输出/合成展示”的固定数据，并同时展示模型、契约版本和未获资格状态。不得让观众误认为该输出来自现场实时模型或已经通过产品资格认证。

任何现场真实模型请求都属于单独的可选技术展示，必须事先显式授权、设置请求预算，并准备失败回退；不能成为主演示路径的必要条件。

## 6. 冻结的主演示流程

主流程控制在可重复完成的范围内：

```text
启动并显示“合成演示数据”
→ Today 查看当前宠物和待复评
→ 新建 Episode
→ 分开填写 Observation 与 Owner Interpretation
→ 完成 NORMAL Safety Check
→ 在 Timeline 查看来源、编辑边界并安排复评
→ 在 Today 完成复评并回链原记录
→ 打开观察计划
→ 在 Us 查看 Baseline 的窗口、样本量、状态和来源
```

安全流程独立展示：

```text
打开 ESCALATE_TO_VET 合成案例
→ 持续显示联系兽医提示
→ 显示模型分析被阻断
→ 强调 Relapaw 不诊断、不提供治疗或用药建议
```

Evaluation 流程作为证据展示，不插入主产品操作造成现场网络依赖。

## 7. 数据与隐私边界

- 演示页面必须持续或在明显位置标明合成数据；
- 演示者不得临时输入观众真实姓名、邮箱、宠物医疗信息或可识别故事；
- 录屏前 reset 到固定数据集，录屏后不保留现场临时输入；
- 截图和视频只能包含合成数据；
- 演示数据库、日志、导出物不得提交 Git；
- 应用日志不输出完整 Episode 正文或 Secret；
- 若观众希望试用，只允许在单独重置的演示实例中输入虚构数据；这不等于真实用户试用。

## 8. 受控线上预览的附加门禁

当前不要求实现线上预览。未来确需远程访问时，必须在部署前满足：

- 使用平台层访问控制、短期密码保护或受邀链接；
- 只使用合成数据，并在固定周期自动 reset；
- 禁止上传真实资料，页面显著标注“演示环境，不要输入真实信息”；
- 禁用 AI Provider、导出、长期保存和任何第三方遥测；
- 使用 HTTPS、严格 CORS、安全 Header 和受限日志；
- 设定明确下线时间，到期删除实例和演示数据库；
- 不宣传为公开 Beta，不收集真实用户反馈档案。

若无法做到平台访问控制，则不建立线上预览，改用本地演示、录屏或截图。

## 9. 实施交付清单

后续代码批次只围绕演示可靠性，不实现账号：

1. **Demo configuration**：增加明确的 demo 环境配置和 AI 总开关；
2. **Synthetic dataset**：实现版本化、确定性、事务化 seed；
3. **Safe reset**：实现只针对固定 `.demo` 数据库的重置；
4. **Built frontend serving**：让 FastAPI 在 demo 模式提供构建产物和 SPA fallback；
5. **Launcher**：实现 `start/reset/verify/stop`；
6. **Preflight**：验证依赖、迁移、数据集、端口、健康检查和关键 API；
7. **Operator guide**：准备演示前、现场故障、演示后清理步骤；
8. **Regression**：自动测试、production build、fresh demo、重复 reset 和完整人工演示。

## 10. 验收条件

### 10.1 启动与恢复

- 从干净的演示数据库可通过单一入口完成 build、migration、seed 和启动；
- 第二次启动不会复制数据或破坏当前数据库；
- reset 只操作固定演示路径，并能恢复完全一致的数据集版本；
- 缺依赖、端口占用、迁移失败、seed 失败或版本不兼容时明确停止并给出可行动错误；
- 断网状态下除首次依赖安装外，主演示路径仍可完成；
- 关闭后不残留占用端口的后台进程。

### 10.2 安全与真实性

- 服务只监听 `127.0.0.1`；局域网其他设备不能访问；
- 默认配置不包含真实 API Key，网络抓包确认没有 Provider 请求；
- UI 和 API 都阻止创建新 AnalysisRun；
- 所有展示数据均能追溯到合成 seed 文件，无真实个人数据；
- 应用清楚显示模型 `NOT_QUALIFIED`，不使用诊断或保证性语言；
- ESCALATE_TO_VET 场景中 Adapter 调用数为 0。

### 10.3 产品流程

- 主演示流程和安全流程各连续运行三次无阻断；
- Episode 创建、Timeline、复评、计划、Baseline 与来源下钻均使用同一演示数据契约；
- reset 后“今日到期”等相对时间状态仍正确；
- 360px、720px 和宽桌面下无导航遮挡或关键操作不可见；
- Chrome 与 Edge 完成键盘、焦点和 reduced-motion 回归；
- 后端测试、前端测试、production build、Alembic fresh migration 和 demo verify 全部通过。

## 11. 明确非目标

- 真实用户注册、登录、数据隔离、导出或删号；
- 公网生产 SLA、PostgreSQL、备份恢复和长期监控；
- 自更新桌面安装包或原生应用；
- 无人值守的公共试用；
- 真实 Provider 的稳定可用性；
- 通过演示数据证明模型已经获得产品资格。
