# Relapaw 产品体验 Beta 使用手册

## 开始使用

1. 按 [README](../README.md#从空库启动windows-powershell) 启动本地环境，在登录页填入合成邀请邮箱并使用固定本地测试码。Resend 是独立的真实投递模式。
2. 首次登录先确认数据约定，再阅读三页引导。引导介绍事实与理解的区别，以及医疗和 AI 边界。
3. 为宠物建立档案。名字和物种足以开始，其余健康背景、生活环境和头像均可稍后补充。
4. 已完成的引导可从“重看三页介绍”重新查看，不会重置账户状态。

## 移动浏览器与未来 App 边界

- 当前交付是 React/TypeScript/Vite 响应式 Web 应用，不是 PWA、混合应用或原生 App；没有 Service Worker、离线业务缓存或原生打包框架。
- Web 页面已针对 320–430 CSS 像素手机宽度、手机横屏、小高度、平板和桌面建立响应式布局；应用壳层集中处理浏览器安全区变量，底部导航占据真实布局空间，不用整页缩放伪造适配。
- 文件选择仍使用浏览器 `<input type="file">`。前端只做类型、非空和 5 MB 预检，后端继续负责文件签名、租户隔离、完整性、替换和删除门禁；本地预览 URL 会在替换或离开页面时释放。
- 未来若放入 WebView，原生容器仍需实现并验证：系统返回手势与 Web 历史协调、文件/相机权限、外链策略、状态栏与手势区注入、下载/分享能力、生命周期恢复和安全存储。Web 层没有预建无调用点的原生桥。
- 自动化浏览器视口只能证明响应式 Web 行为，不能替代 iOS Safari、Android Chrome、真实 WebView、刘海设备和真实软键盘测试；这些仍是发布前的真机验收项。

## 日常记录

- 在“理解”页先写下当时的原话；事实、主人的理解和更多计量信息都是按需补充项。
- Safety Check 只用于识别当前危险信号。出现危险信号时，应按页面提示联系兽医或急诊，系统不会继续调用外部 AI。
- “加入观察计划”用于把多天的相关记录放在一起比较。没有计划时，记录会明确保存为独立记录。
- 保存后可在“足迹”查看记录详情。原话、观察事实、主人理解、媒体和修改历史彼此分开；技术来源默认折叠。
- 编辑记录会新增版本，不会覆盖旧版本。

## 照片和视频

- 宠物档案支持 JPG、PNG 和 WebP 头像，可替换或删除。
- 图片和视频先附着到具体记录、生活事件或关系事件，再作为长期变化的证据引用。
- 可以填写拍摄时间和原始说明；系统保存类型、大小、哈希和修改历史。
- 媒体候选理解必须由用户确认。第一阶段不依据图片或视频诊断疾病。

## “我们”页面

- “宠物档案”保存客观资料、主人观察、头像和生活环境。
- “长期变化”集中展示日常基线、经确认的长期记忆和重要生活事件。
- “关系与家庭”保存照护背景、家庭环境以及主人—宠物或宠物—宠物事件。
- 照护背景完全可选；只有明确开启并选择的字段才能进入新的 AI 上下文，撤回后不再使用。
- 互动模式只在多条、跨时间记录形成足够证据后成为候选，并保留支持记录、矛盾记录和置信限制；用户可确认、拒绝、修订或撤回。

## AI 辅助

- AI 默认关闭。关闭时建档、记录、复评、搜索、媒体、长期记忆、关系事件、导出和本地备份仍可使用。
- 获得资格的模型只能整理已有记录、比较近期变化、组织复诊时间线，并基于批准且未撤回的受控资料提供非诊断性说明。
- 输出固定区分记录事实、主人理解、相关背景、不能确定、继续观察、联系兽医和资料来源。
- AI 不提供诊断、治疗、药物或剂量，也不能覆盖原始输入或 Safety 结果。
- 已选择并验证阿里云百炼 Qwen 北京地域固定模型，facts v7 与 guidance v4 已完成资格评估、运行时登记及各一次合成数据真实产品 smoke；AI 仍默认关闭，后续真实调用或长期启用必须重新获得明确授权。

## 数据管理

- 账户导出包含宠物、记录、修订、照护背景、关系事件、互动模式、媒体元数据和 AI 运行审计信息。
- 删除记录或到期清理账户时，相应派生数据和受管媒体按生命周期规则清理。宠物档案可以归档并恢复，归档会保留原数据。
- 本地备份包含数据库、已登记的可用附件与头像；备份和恢复前应停止服务，按[本地数据手册](LOCAL_ALPHA_GUIDE.md#备份与恢复)操作。
- 不要把 API Key、验证码或完整私人数据放入聊天、截图、日志或版本控制。

## 当前外部边界

- 本地 Resend 邮箱闭环已验证，但 staging/production 的域名、发件地址和部署配置仍需另行审批。
- 真实 AI 本地资格与最小 smoke 已完成；staging/production 长期启用和部署仍待单独审批。医疗安全内容与正式条款/隐私文本分别等待执业兽医和法律审核。
- 外部状态与人工验收步骤分别见 `PRODUCT_EXPERIENCE_BETA_EXTERNAL_DEPENDENCIES.md` 和 `PRODUCT_EXPERIENCE_BETA_MANUAL_ACCEPTANCE.md`。
# 运行时 AI 资格登记与安全开关

迁移 `20261026_0027` 创建并种入资格 ID `qwen-beijing-20261026-v7-guidance-v4`。记录只包含固定 provider/model、北京端点政策、facts v7 与 guidance v4 契约、受控知识集合版本、脱敏证据路径及 SHA-256；不包含 API Key、原始模型输出或用户数据。

只读检查登记状态：

```powershell
cd E:\Relapaw-ProductExperienceBeta\backend
.\.venv\Scripts\python.exe -m app.qualification_registry status
```

紧急撤销会立即使两条 AI 调用路径 fail-closed，并保留撤销时间和原因：

```powershell
.\.venv\Scripts\python.exe -m app.qualification_registry revoke --reason "operator safety rollback"
```

迁移级回滚使用 `alembic downgrade 20261026_0026` 删除整个运行时资格表；重新升级到 `20261026_0027` 会从版本化清单重建初始 APPROVED 记录。生产环境执行迁移回滚前仍需独立变更审批和数据库备份。

本地启用前必须确认数据库位于 0027、登记状态为 APPROVED、证据摘要未漂移、固定 Qwen 模型和北京端点与清单一致，并且 `backend/.env` 中已经由用户安全配置密钥。不要在聊天、命令输出或截图中展示该文件。随后只在获得单独授权后，将非秘密资格配置指向上述资格 ID、将模型资格设为 QUALIFIED，最后才把 `RELAPAW_AI_ENABLED` 改为 true。关闭时首先把 `RELAPAW_AI_ENABLED` 改回 false 并重启后端；紧急情况同时执行撤销命令。当前阶段必须保持 false。
