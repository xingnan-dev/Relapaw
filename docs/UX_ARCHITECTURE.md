# Relapaw UX Architecture — Phase 0.1

## 设计目标

入口体验应先建立信任与边界，再让用户创建宠物资料。布局借鉴参考图中的大区块、卡片层级、浮动底栏与渐进展开方式，但不复制其视觉样式。Phase 0.1 只冻结信息架构、流转和低保真交互，不做品牌视觉定稿。

## 首次进入流程

```text
Splash（随初始化结束，不用固定假倒计时）
  -> 3 页 Onboarding
     1. 看见事实：Observation ≠ Interpretation
     2. 理解变化：结合基线与长期记录
     3. 安全边界：异常健康风险优先联系兽医
  -> Pet Setup
     -> 创建成功：Today
     -> 暂时跳过：Today 空状态
```

完成标记保存在本地；再次打开不会重复 onboarding。宠物创建成功后立即成为当前宠物。没有宠物时不伪造示例数据，而是显示可行动的空状态。

## 主信息架构

- **Today**：当前宠物、日期上下文、今日关注、观察计划、最近变化。
- **Understand**：输入事件，先拆分客观观察与主人解释；媒体按钮在本阶段仅占位。
- **Timeline**：按时间查看 Episode，可展开查看 Observation 和 OwnerInterpretation 两个独立视角。
- **Us**：Pet / Owner / Relationship 三类长期模型入口与边界说明。

四个主页面使用底部浮动 pill 导航横向切换。主导航不使用整页模态或卡片堆叠，避免让长期记录产生“刷卡即丢弃”的误解。

App Shell 使用固定视口网格：Header、可独立滚动的 Main、占据真实布局空间的 Bottom Navigation。底栏不得覆盖 Main 内容；移动端安全区通过 `safe-area-inset-bottom` 保留。表单控件获得焦点时由 Main 自身滚动保证可见，而不是依赖页面内容从固定导航后方穿过。

## 页面层级与弹出方式

- 一级 Tab：160–200ms 淡入与小幅位移，保持底栏稳定。
- Timeline 到详情：未来使用约 220–260ms 横向 push，返回时保留列表位置。
- 创建/编辑：从底部进入全屏页面；短选择器不冒充完整编辑页。
- 宠物选择、日期和筛选：bottom sheet。
- 安全升级与破坏性确认：居中 modal，明确阻断背景操作。
- 非阻断反馈：toast 或页面内状态，不用 modal。
- Timeline 卡片：原位展开，Observation 与 Interpretation 并列或上下分区展示。

所有动画尊重 `prefers-reduced-motion`；减少动态时关闭非必要位移和过渡。转场只表达层级，不制造等待。

## 可访问性要求

- 导航和主要动作保留清晰文字标签与足够点击区域，不只依靠图标或手势。
- 当前 Tab 使用 `aria-current`；展开内容使用 `aria-expanded`；加载和错误反馈使用语义状态区域。
- Observation 与 Interpretation 依靠标题和结构区分，不能只靠颜色。
- 键盘焦点顺序遵循视觉顺序；键盘打开时底栏不得遮挡输入框。
- Safety Banner 必须在页面内持续可见，不能只用会消失的 toast 表达医疗安全信息。
- 对比度、字号缩放、屏幕阅读器与 reduced motion 在高保真阶段继续验收。

## Understand 的“双镜头”契约

```text
主人原始输入
  -> Observation：看见/听见/发生了什么
  -> Owner Interpretation：主人认为它意味着什么
```

两个区块始终使用不同标题、字段和提交路径。未来分析结果也必须分别返回，不能用单一“结论卡”覆盖证据、不确定性与安全状态。

## 页面状态

每个读取型页面至少覆盖：loading、content、empty、error/retry。入口恢复无效宠物 ID 时清除本地引用并重新读取宠物列表；接口不可用时显示错误状态，不自动制造数据。

## 本阶段不采用的参考模式

- 不采用 Tinder 式卡片左/右滑作为核心判断，因为它会把复杂行为压缩成二选一。
- 不采用高密度仪表盘和伪精确百分比，避免制造医疗或情绪确定性。
- 不采用强烈游戏化连续打卡作为关系评价。
- 不用宠物照片替代证据结构；照片未来只是观察来源之一。
- 不复制参考图的配色、字体、插画和商业卡片内容。

## 下一阶段接口

视觉设计阶段可在本架构之上定义品牌色、排版、间距、图标、组件 token 与高保真原型；不应改变 Observation ≠ Interpretation、安全优先、四页主导航和真实空状态这些已冻结原则。如需改变，应先更新本文件并记录理由。
